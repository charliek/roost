# mac/

macOS packaging for Roost. The app itself is the Rust + iced UI in
`crates/roost-iced`, the same one the Linux package ships; this directory
holds what turns its cargo binary into a signed, updatable `.app`.

| Path | What it is |
|------|------------|
| `scripts/bundle-iced.sh` | Builds `roost-iced`, `roostctl` and `roost-session` and assembles the `.app`: stamps the plist, embeds both helpers and Sparkle.framework, signs inner to outer, and self-checks the result. |
| `scripts/bundle-lib.sh` | The stages `bundle-iced.sh` sources: version derivation, the icon pipeline, the helper embeds, the signing machinery. |
| `scripts/make-dmg.sh` | Packages a bundle into a drag-install DMG. |
| `scripts/notarize.sh` | Submits a bundle or DMG to Apple's notary service and staples the ticket. |
| `scripts/update-appcast.py` | Adds a release's entry to `docs/appcast.xml`. |
| `scripts/verify-sparkle-key.sh` | The release's Sparkle key check (`keys/README.md`). |
| `Resources/Info.plist.template` | The app's `Info.plist`, with `@VERSION@`, `@BUNDLE_ID@` and `@APP_NAME@` filled at bundle time. |
| `Resources/*.entitlements` | Hardened-runtime entitlements for the app, the embedded `roostctl` and the embedded `roost-session`. Each file's comment gives its reasoning; `tools/roosttest_unit/test_mac_entitlements.py` pins them. |
| `Resources/AppIcon.icns`, `AppIcon.icon/` | The app icon, both generated by `packaging/icon/regenerate.sh`. |
| `keys/` | The committed Sparkle public key. |

## Two identities

`bundle-iced.sh` assembles one of two identities, chosen by
`ROOST_BUNDLE_IDENTITY`:

| | `dev` (default) | `production` |
|---|---|---|
| Bundle | `mac/build/Roost-Iced.app` | `mac/build/Roost.app` |
| Bundle id | `ai.stridelabs.Roost.iced` | `ai.stridelabs.Roost` |
| Executable | `Contents/MacOS/Roost-Iced` | `Contents/MacOS/Roost` |
| Socket, state, logs | `~/Library/{Caches,Application Support,Logs}/Roost-iced/` | `~/Library/{Caches,Application Support,Logs}/Roost/` |
| Sparkle feed | none, unless both feed values are given | required: the feed URL and the committed public key |

A dev build runs beside an installed `Roost.app`: its id, paths and
process name all differ. The production identity is what `release.yml`
ships, and its id and paths are the ones the retired Swift app used, so it
updates an installed copy in place.

## Build

libghostty-vt must be built once first (`./third_party/ghostty/build.sh`,
or `make ghostty`). Then:

```bash
make bundle-iced                              # debug, dev identity
./mac/scripts/bundle-iced.sh                  # release, dev identity
open mac/build/Roost-Iced.app

ROOST_BUNDLE_IDENTITY=production \
  ROOST_BUNDLE_SPARKLE_FEED_URL=https://charliek.github.io/roost/appcast.xml \
  ROOST_BUNDLE_SPARKLE_ED_PUBLIC_KEY="$(cat mac/keys/roost-sparkle-ed-public-key.txt)" \
  ./mac/scripts/bundle-iced.sh release        # the shipped Roost.app
./mac/scripts/make-dmg.sh 0.1.0               # mac/build/Roost-0.1.0.dmg
```

Signing is ad-hoc unless `ROOST_DEVELOPER_ID_IDENTITY` names a Developer ID
certificate. An ad-hoc build launched from Finder meets Gatekeeper's
"downloaded from the internet" dialog; `xattr -dr com.apple.quarantine
mac/build/Roost-Iced.app` clears it.

## Tests

* `make e2e-iced-bundle` launches the dev bundle and runs the bundle smoke
  against it; `make e2e-iced-sparkle` assembles a TEST-keyed bundle and runs
  the Sparkle lane. Both are macOS-only.
* `make test-mac-scripts` runs the shell tests for `notarize.sh` and
  `verify-sparkle-key.sh` (no macOS needed).
* `make test-harness` includes the plist, entitlements and Sparkle-plist
  checks (`tools/roosttest_unit/`).
* CI's macOS `iced-build-e2e` cell assembles both identities and asserts
  their contents, signatures and DMG.
