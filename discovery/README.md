# Discovery notes

Working notes, not product commitments. These files live outside
`docs/` so they are not built into the public site — Zensical has
no equivalent of MkDocs `exclude_docs`.

| Note | What it is |
|---|---|

| [swift-retirement.md](swift-retirement.md) | **Executed by plan 089 (v0.1.0).** Retiring the Swift `Roost.app`: iced takes over the Mac identity, the Mac feature gaps to close (with what plan 073, the first gap release, shipped or deferred), the removal inventory, the `roost-legacy-swift` extraction, issue triage, and phases: Swift frozen, gap releases, then the v0.1.0 cutover. |
| [text-rendering.md](text-rendering.md) | Terminal and chrome text in iced, for later (fonts look good today; chrome size in chrome-themes.md comes first). | [sessions-everywhere.md](sessions-everywhere.md) | Making sessions the normal backend on every machine so work doesn't depend on where you sit: what already works for several clients, the gaps a real Mac→Pop!_OS setup hit (finding the session when `XDG_RUNTIME_DIR` differs, window size with several clients, reconnect, daemon lifecycle, where session tabs are worse than in-process), a possible order, and what retiring in-process local tabs would involve. |
| [mobile-client.md](mobile-client.md) | A Flutter mobile client (Android first; tablets, foldables and phones) for host sessions: what an Android spike proved end to end (libghostty-vt, `roost-vt`, `roost-ipc` and russh, reaching a real `roost-session`), the crate layout (`roost-client` extracted from `roost-iced`, an FRB crate, `mobile/`), the SSH transport choice, sizing with several clients, mobile UX in place of hotkeys, and an MVP order. Its prerequisites are merged; the MVP branch starts after the protocol-7 release. |
| [protocol-7-release.md](protocol-7-release.md) | **Decided (2026-10-28):** the next release and the source of truth for its milestone plans. M1: Ghostty main with Zig 0.17, OSC 7501 program status, per-tab memory. M2: the Linux session socket under HOME (G1). M3: tab size ownership (G2). M4: tab environment by opener (G9). M5: the first `roost-client` extraction. One session-protocol bump, 6 → 7. All five milestones and pre-release plans 087 (hardening) and 088 (Kitty graphics) are merged. Released as v0.0.27 (2026-11-03). |
| [chrome-themes.md](chrome-themes.md) | Chrome comfort, revised 2026-11-08 to Charlie's order: chrome size first (an inventory of every chrome size, a `ChromeMetrics` seam, one `chrome-font-size` key plus Increase/Decrease/Reset actions), then chrome color themes and overrides (#584) and opacity in either order, then "looks" that switch several appearance keys at once. Following the system light/dark setting (#164) is deferred, with its findings kept. A phased roadmap, one plan per phase. |
| [split-panes.md](split-panes.md) | Split panes after the non-goal was lifted (DL-35). **Not planned**: a possible future feature, behind every other direction here. Written around Charlie's goals if it is built: agents that drive panes, several agents in one window, a terminal beside an agent. How herdr, cmux, zellij, WezTerm, tmux and Ghostty let agents control panes; why a client-only 2-up doesn't meet the goals; the leading shape, a session-owned layout whose leaves are today's tabs (no protocol bump, `ROOST_TAB_ID` unchanged); a phased roadmap (P0 to P6, XL overall). |
| [agent-integration.md](agent-integration.md) | The main feature track, after backlog Plan A: stop writing into users' agent configs and make agent integration better at once. What Roost writes today; per-agent delivery through the tab environment, proven live (Claude `CLAUDE_CODE_PLUGIN_DIRS`, opencode `OPENCODE_CONFIG_CONTENT`); fusing OSC 7501, hooks and the foreground process into one state. **Decided 2026-11-08:** Roost removes its own entries automatically once nothing needs them, only where it can prove it wrote them, and the startup prompt becomes "Agent integration" (draft copy and mockup). Recommended: Codex on 7501 alone with no shell function (its panel and palette rows already update and focus the tab, proven live), and ending ownership once an agent's process is gone. A roadmap of phases 0 to 8, one plan each (Phase 3 is two), with tests and exit criteria. Supersedes parts of agent-watching.md. |
| [backlog-triage-2026-11.md](backlog-triage-2026-11.md) | The open backlog after v0.1.0, split into separate plans, recommended in the order A, C, B, D, E: A v0.1.1 quick wins (#134 first, #697), C agent safety (#706, #261), B scrollback and find (Ghostty bump, #707, #167, #169), D everyday actions and the terminal menu (#710, #165, #162, #163), E paths and live config (#708, #709). Dead agent state (#519, #621) and resume on restore go to agent-integration.md. Records the 2026-11-08 GitHub pass: #570 and #388 closed, #706 to #714 filed, 21 issues commented on, eight retitled, about 40 relabelled. |
